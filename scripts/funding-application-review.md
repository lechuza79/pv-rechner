# Programme-specific application review

This is part of the existing funding crawler/reviewer workflow, not a separate automatic publication path. Use `npm run foerder:probe -- --antragsvorrat` to find missing or outdated procedures. Process it within the agreed review batch; do not launch an unbounded catalogue-wide model run.

1. Read the official programme page and its linked current guidelines, application form/portal, document checklist and payment instructions. Preserve fetched evidence with the existing source reader and factual UTC observation times. Blocked or ambiguous sources remain open.
2. Extract only explicit instructions: timing relative to purchase/contract and approval, how/where to submit, implementation deadlines, evidence of completion and payment. Keep the source's order. Never assume that every programme requires approval before purchase. Distinguish PV, balcony and heat-pump procedures using `nur` on steps/documents. If contact or portal differs by technology, do not publish a shared contact/portal; put the scoped instruction in a step.
3. Store the reviewed procedure in `FundingProgram.application` using the type in `lib/funding-application.ts`: actual UTC `checkedAt`; `sources` with URL, descriptive title and a short supporting quotation; `steps` with title, text, kind and supporting `evidenceUrls`; optional documents, contact and portal with their evidence URLs. Every assertion must point to a source actually read. Missing facts stay missing; an incomplete/unverified procedure must not be labeled as complete.
4. Keep existing conditions consistent and complete. Application instructions supplement, rather than silently delete, catalogue conditions. Register all newly found official source URLs in the existing source inventory and case dossier. Follow the normal independent verification, evidence parity, decision report and `/api/alert` requirements. A structural validator is not factual approval.
5. Before catalogue publication, run `npm run foerder:probe -- --antragsdaten <json-file>` on the application object. The normal setup/resync path rejects malformed or future-dated application evidence. It does not publish a candidate by itself. Set `contentUpdatedAt` to the actual time of a substantive editorial change, never for unchanged fetches, checks or deployment.
6. The programme watcher also watches application source documents. Changed evidence invalidates the older walkthrough and puts the programme back into review; an unreadable source creates an unresolved check, never a negative funding decision. Re-read the affected instructions, update/remove stale application data and use the normal release process. The UI retains the existing conditions and official programme link when no usable walkthrough is available.

A successful task must report separately: crawler support implemented, programmes actually researched, procedures still missing, and publication status. Do not claim the catalogue has complete application instructions merely because the schema was added.
